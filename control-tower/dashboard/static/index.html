How it works

          

            

              
The shipment is parked safelyIf nobody acts within a short window, it joins the Human Action queue and the run carries on. Nothing is written for it.

              
Open & ContinueBetween shipments, the run looks that shipment up again in its own browser and brings the carrier tab to the front of its Edge window, at the verification step.

              
You do only the verificationFor Grimaldi: type the security code and press Search. The automation never reads, solves or types a code.

              
ATLAS takes overThe page is read twice to confirm the right shipment is there, then extraction, validation, Hub write and read-back run by themselves. Only a write that reads back is a success.

How a job runs

        
    
          
  1. eHub: Under Clearance → Manage → DocumentsOnly a record whose status is exactly Under Clearance is opened. In its Documents section, the document whose name starts with “Bill Entry” is taken, and the number after it becomes the job's identifier.
    2. 
          
  2. Read and extractEach field is found, missing or ambiguous. A missing value is never filled in; two different values are never chosen between.
    3. 
          
  3. Validate — the gateThe BL/AWB must match the Hub, every required field must be present and the duty must add up. Anything else stops the job.
    4. 
          
  4. Fill the approved templateOnly its input cells are written; its formulas compute. The saved file is opened again and read back before it counts.
    5. 
          
  5. Send through Microsoft 365On Send PO, from the ATA mailbox. Verified when it appears in Sent Items. The same document is never sent twice by accident.
