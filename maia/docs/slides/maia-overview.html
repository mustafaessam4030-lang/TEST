01The one rule

Maia decides what to ask for.
She never decides how it is fetched.

No browser

The model's entire reach into SIS is one string: a serial number, re-validated server-side. It cannot click, navigate or read a page.

No credentials

The agent process holds no SIS secret and has no tool that accepts one. Credentials are resolved at the moment of use, by the worker.

No SQL

Storage sits behind a repository interface. The model never writes a query, and never sees the store it is reading from.

Everything downstream follows from this: a wrong answer has to be manufactured somewhere, and there is nowhere left for it to be manufactured.

Every step records its start, end, duration, URL and outcome. On failure it also captures a screenshot and trimmed HTML, and maps the exception to one of sixteen typed error codes.

Step 9 is new. PERSIST used to be a footnote after the answer was returned. It is now part of the run — and it runs before the run is marked successful.

04The problem with the detail page

SIS renders inside its own scrolling pane.

The equipment details sit below that pane's fold, and the parts groups below those. Scrolling the window moves nothing.

Read before scrolling and you find an empty page — which is indistinguishable from a website that changed, unless the scroll is an explicit, reported step.

So extraction scrolls the pane, not the window, waits for the SPA to settle, and only then reads. Reaching the bottom is not the end: an SPA renders the section a moment after the scroll that asked for it.

07What happens when it goes wrong

Every failure is typed, and none of them is a partial answer.

EXTRACTION_ERROR

The wrong machine

The machine serial on the page must equal the serial that was searched. A mismatch stops the run twice — in the adapter, and again as a fatal validation violation.

A confident answer about the wrong machine is the worst thing this system could produce.

WEBSITE_CHANGED

The section never appeared

Scrolled the pane, waited for the render, and the equipment details still were not there — or a required field could not be read.

Engineering event, not an empty answer handed to a customer.

PERSISTENCE_FAILED

Read, but not saved

Extraction and validation both passed and the file could not be written.

Maia is told the lookup did not complete. A result nobody can read later did not happen.

An error response carries no data object at all — so there is nothing for the model to paraphrase into a plausible-sounding answer.

10Three rules the store enforces

Nothing is discarded

raw_data.extracted_fields keeps every field the page gave, including keys the schema has no column for.

A field with no column is still evidence. Dropping it means driving a browser again to get it back.

A missing value is null

Never an empty string, never a default, never a guess — and field_provenance records why.

"The source does not publish this" and "we failed to read it" are different facts, and the record keeps them apart.

A failed save fails the lookup

PERSIST runs before the run is marked successful. No file, no success.

A run recorded as SUCCESS whose data was never written is a lie told to every later reader.

Never written: passwords, cookies, tokens, authorization headers, session state, MFA codes. Every payload is scrubbed by key and by exact value — so a credential cannot reach disk even under an innocent-looking key.

11One guard worth its own slide

A record is labelled by the source that actually produced it.

Real run 
"source": "Caterpillar SIS",
"source_system": "cat_sis"
Test fixture 
"source": "Local test fixture
           (NOT Caterpillar SIS)",
"source_system": "local_fixture"

The label comes from the source registry, never from a default. Writing "Caterpillar SIS" onto a row that came from a test fixture is the one mislabelling that would make every other guarantee in this platform worthless — so a test asserts it cannot happen.

Two defects found this way, neither by reading code:

  • An SPA renders the target section after the scroll that asks for it — so stopping at "reached the bottom" found an empty page and called it a changed website.
  • Making persistence file-backed changed the exception from DATABASE_ERROR to OSError. A full disk while caching a SERIAL_NOT_FOUND would have replaced the correct answer with an opaque crash.

Both are now covered by tests that fail if the behaviour returns.
