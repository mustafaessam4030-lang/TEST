# Evaluation report

Measured on 2026-10-14 in the build container: 4 vCPU, 15 GB RAM, no GPU, Python 3.13, PyMuPDF 1.28.2, tesseract 5.3.4. Every number below came from `scripts/run_eval.py` or the commands listed. Nothing is estimated.

## What was evaluated

- **Documents.** Synthetic, non-confidential PDFs generated by `scripts/make_samples.py`, with invented products and values:
  - HX-200 pump manual, Rev B (6 pages): spec and torque tables, a procedure with warnings, a two-column troubleshooting page, and a blank page;
  - HX-200 manual, Rev A (superseded, with different values);
  - CV-90 gearbox datasheet;
  - TL-5 inspection checklist, a 2-page image-only scan with speckle noise;
  - a blank PDF and a corrupted file;
  - one duplicate upload.
- **Tuning set** (`eval/questions.json`, 41 questions): exact values, units, part numbers, procedures and warnings, tables, OCR, multi-document, conflicting revisions, ambiguous equipment, unsupported questions, follow-ups and small talk. **The system was developed against this set**, so its numbers are optimistic.
- **Held-out set** (`eval/heldout.json`, 17 questions): written after tuning, with new phrasings and facts.
- **Scoring.** Deterministic checks only; no LLM judge.
  - *Behaviour*: the answer status matches the expectation (answer, abstain, clarify, small talk).
  - *Correct*: the right behaviour, every `must_include` string present in the claims, and no `must_not_include` string in the main claims.
  - *Retrieval recall@k / MRR*: an expected document and page is among the selected passages.
  - *Citation hit / precision*: the expected document and page are cited, and the share of cited pages that are expected.
  - *Unsupported claim*: a claim containing a number or identifier that its cited passages don't contain, re-checked independently of the answer pipeline.
  - *Invalid citation*: fails the store re-validation.

### Held-out history, reported in full

The first held-out run exposed two defects. Results of that first run:

| | hashing | fastembed |
|---|---|---|
| Answerable correct | 66.7% | 91.7% |
| Abstention on unanswerable | 100% | 75% |

1. **Wrong-topic answer** (fastembed only). "What is the HX-200 pump efficiency?" was answered with true but irrelevant specification rows. Strong semantic similarity had bypassed the topic check entirely. *Fix:* semantic similarity now only lowers the topic-coverage bar, from 0.5 to 0.25.
2. **Incomplete troubleshooting answer.** "Why can't the system reach rated pressure?" returned only the symptom sentence. *Fix:* "why …" questions now return whole symptom/cause/remedy blocks.

The table above shows results after both fixes, so the held-out set is no longer fully unseen. The fixes traded two fastembed held-out answers (h-02, h-06) for zero wrong-topic answers, the safer direction for engineering use.

### Remaining misses

| Id | Question | Result | Why |
|---|---|---|---|
| spec-08 (hashing only) | How much oil does the CV-90 gearbox hold? | abstained | "hold" vs "capacity": vocabulary gap |
| multi-02 | Which oil grades are recommended for the HX-200 and the CV-90? | abstained | "grade" vs "ISO VG": vocabulary gap |
| amb-02 | What is the oil change interval? | answered from the CV-90 only, with an "equipment not named" caveat | the HX-200 says "hydraulic fluid", not "oil", so the ambiguity is not detected |
| h-01 (hashing only) | What operating temperature range does the HX-200 support? | abstained | "support" and "range" aren't in the row |
| h-02 | How fast does the CV-90 output shaft turn? | abstained | "fast/turn" vs "speed" |
| h-06 | Is it safe to service the HX-200 pump straight after running it? | abstained | the CAUTION says "surfaces can exceed 80 C … allow the pump to cool" |

All of these are vocabulary gaps between the question and the document. The system abstains or caveats rather than answering wrongly. No miss produced a fabricated value.

## Performance and scale

A 240-page PDF was made by repeating the Rev B manual 40 times, giving 920 passages.

|---|---|---|---|
| hashing | 11.1 s (46 ms/page) | 6 / 13 ms | 110 MB |

The 3.5 GB peak came from fastembed's default batch of 256 padded passages, and was found by this measurement. Embedding speed on this container was ~60–90 ms per passage regardless of thread count. Faster CPUs should do better, but that was not measured.

## Automated tests

`python -m pytest`: **90 passed**, run with `EKA_TEST_MODEL_DIR` pointing at the local bge-small model. Without it, the run gives 88 passed and 2 skipped, the two skips being the real-embedding tests. Which suites use real components and which use mocks is tabulated in the README ("What is real and what is mocked"); only `test_generation.py` (Ollama) is mocked.

What the tests cover:

- **Text and extraction:** identifier-preserving tokens and number canonicalisation; tables with headers and captions, two-column order, warnings, blank pages, OCR, OCR disabled, and corrupted, non-PDF or encrypted input.
- **Chunking and ingestion:** chunk pages, sections, table rows and steps; ingestion statuses, page records, duplicates, re-index without duplicate chunks, and revision supersession.
- **Retrieval:** table-row recall, the document filter applied before scoring, unknown identifiers, and trace reasons.
- **Answers:** exact values with pages; revision handling; part numbers; stated unit conversions; procedures with warnings; four unsupported questions; the missing-model message.
- **Clarification:** clarify-first, with no values and options carrying `doc_id`. Answering through a reply or an option click, and the cells on spec rows.
- **Conversation behaviour:** follow-ups, topic change, OCR labelling, document scope, comparison, library and help intents. Also the semantic-gate regression, "why" questions and the unnamed-equipment caveat.
- **Empty-answer regression:** 9 adversarial inputs, all of which return a status and a non-empty message.
- **Citation validation:** a wrong page, an invented excerpt and an unknown chunk are all rejected; invented numbers and part numbers are detected.
- **Embeddings:**
  - `hashing` is labelled keyword-only.
  - `auto` without a local model falls back without downloading, and offline loading refuses to fetch.
  - With the real bge-small model, vectors are normalised and 384-dimensional, and it ranks "hold" to "capacity" by meaning.
- **Ollama path** (stand-in server, **mock**):
  - valid claims are accepted;
  - an invented value or source id is rejected;
  - empty, non-JSON or invalid-status output, a timeout or an unreachable server fall back to extractive;
  - model abstention is respected;
  - there is no model call without evidence.
- **API end to end:**
  - upload, processing, duplicates, page status, chat and follow-up, page PNG, PDF file;
  - 415/400/413 errors, corrupted upload, 404s, validation, delete, token enforcement;
  - streaming stages and answer;
  - saved and reloaded history, search, rename, delete, follow-ups after the memory is cleared, retry, feedback;
  - document search (native and OCR) with highlighted pages;
  - suggestions that verify as answerable.

`tests/ui/run.sh` runs the browser suite: **142/142 checks pass** in Chromium against fresh real servers, at desktop, tablet and phone sizes in light and dark. A mock model was used only for the slow-response and Stop checks. The interaction list and the defects it found are in [UI.md](UI.md).

Evaluation-set note: `amb-01` and `amb-02` now expect clarify-first behaviour, so no values are shown, and no longer require the values in the answer. Every metric in the results table was re-run after this change and is unchanged.

## Not tested

- Answer quality, latency and memory with a real Qwen model in Ollama: only the protocol was tested, against a stand-in server.
- Ollama embeddings (`EKA_EMBEDDER=ollama`): implemented, never run.
- Real engineering manuals: complex layouts, borderless tables, non-English text, very large (1000+ page) documents.
- Scans at low quality or skewed; the sample scan is clean apart from speckle.
- Concurrent multi-user load, and long-running stability.
- Browsers other than Chromium; Windows and macOS hosts; real touch devices; screen readers.
- The UI with a real Ollama model: only the 6-second mock model was used for slow-response and Stop.
- Snowflake: not used.
